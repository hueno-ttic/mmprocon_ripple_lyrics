# Ripple Lyrics - 水の循環 - — QA Regression Checklist

コードを改修した際は、必ず以下の項目を \`browser_subagent\` を用いて**視覚的（スクリーンショット・録画）**に確認し、品質を担保すること。

## 1. アプリ起動とLake UI（選曲画面）の確認
- [ ] アプリ起動時、コンソールにエラー（500エラーや未定義エラー）が出ないこと。
- [ ] Lake UIが正常に描画され、水面シェーダーと波紋エフェクトが動いていること。
- [ ] 各曲のDOMラベル（タイトル・アーティスト名）が3D空間上の波紋に追従して表示されていること。
- [ ] マウスホバー時に曲名ラベルがスムーズに拡大し、クリックすると楽曲のロードが開始されること。

## 2. 楽曲のロードと初期化
- [ ] 曲をクリックした後、ローディング画面（"波紋を読み込んでいます..."）がフェードインすること。
- [ ] TextAlive APIが正常に初期化され、シーンクラッシュや強制的に選曲画面へ戻されるバグが発生しないこと。
- [ ] 楽曲再生画面へ遷移した際、新しく実装されたグラスモーフィズムのUI（再生/停止ボタン、戻るボタン）が表示されること。

## 3. 楽曲再生時の3D演出と同期機能
- [ ] 再生ボタン（またはSpaceキー）で楽曲が再生/一時停止できること。
- [ ] 楽曲の進行に合わせて歌詞が正しく出現し、演出（例：シャッターチャンスのポラロイド、こたえての視点移動など）が連動すること。
- [ ] 演出用のオブジェクト（テキストスプライト等）が視認できない（黒背景と同化している、透明度が0のまま）といった描画バグがないこと。
- [ ] マウス移動による視差効果（パララックス）や、クリック時の波紋エフェクトなどのインタラクションが動作すること。

## 4. 楽曲切り替えと終了時のリソース破棄 (Destroy処理)
- [ ] 「湖面へ戻る」ボタン、またはEscapeキーを押した際に、現在の楽曲シーンが完全に破棄され、Lake UIへ正常に戻ること。
- [ ] 別の楽曲を選択した際、前の楽曲のイベントリスナー（Spaceキーの競合など）やThree.jsのリソース（テクスチャ、ジオメトリ）が残存せず、クリーンな状態で再生が開始されること。
- [ ] 楽曲が最後まで再生された際（`onStop` イベント発火時）、正常に完了状態となりUIが適切に更新されること。
