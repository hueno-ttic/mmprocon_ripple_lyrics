# CHANGELOG - TAKEOVER (SongTakeover)

本ファイルでは、楽曲『TAKEOVER』（`song-takeover.js`）専用のハッキング＆デコード演出強化、暗号化処理、およびパフォーマンス最適化の歴史を記録・管理します。

---

## 📅 2026-06-05: [Bug Fix & UX Polish] 歌詞の表示持続時間の延長、文字サイズ縮小と全画面配置による衝突防止の最適化、およびPCモニター背景演出の追加

### 変更内容
* **ハッカー風PCモニター背景（DECRYPTION TERMINAL）演出の追加**:
  * 画面中央の背景に、レトロなPCのCRTモニターを模したサイバー＆グラフィカルなパネル要素（`to-monitor`）を追加。
  * モニター外枠にはパープルのネオン発光（`box-shadow`）およびCRT風の画面微小フリッカー（ちらつき）アニメーションを実装。
  * モニターの画面内には、ドットマトリクス状の暗号格子（グリッド線）や走査線（スキャンライン）のエフェクトをレイヤー合成し、本格的なコンソールモニターUIを表現。
  * ヘッダー部にはMac風の赤・黄・緑のクローズ/最小化ボタンやセッションタイトル、フッター部にはAES鍵情報・ポート番号・安全な接続ステータスを示すインジケーターを常時配置。
  * `destroy()` メソッド内に、モニター要素の確実なDOM破棄処理を追加し、メモリリークを防止。
* **グリッド配置領域をモニター画面内（インサイド・モニター）に最適化＆境界クランプによる飛び出し防止**:
  * 歌詞が散らばるグリッドの基準値を、モニター内側の表示エリア（`leftPct: 8%〜92%`, `topPct: 17%〜75%`）に設定。
  * **暗号文スライディングウィンドウ最大文字数の制限 (最大18文字に制限)**:
    * 日本語歌詞は暗号化（AES-GCM）されてBase64にエンコードされると3〜4倍の長さ（最大80文字以上）になり、画面枠を大きくオーバーフローする原因になっていました。これに対し、スライディングウィンドウの表示枠を **最大18文字** にクリップ（`Math.min(..., 18)`）し、暗号表示をコンパクトに保ちました。
  * **暗号テキストと平仮名・漢字（復号テキスト）の双方向正確サイズ見積もり**:
    * 暗号状態（半角英数モノスペース＋レタースペース）と復号状態（全角日本語文字）のそれぞれ異なる占有幅を正確に見積もり、その最大値（`Math.max`）を `widthPx` として算出。
    * 各歌詞ブロックの占有幅・高さを考慮した数学的クランプ（`leftPct`を`6%〜(94% - 幅)`、`topPct`を`16%〜(81% - 高さ)`の範囲に制限）を導入。
    * これにより、文字数が多い歌詞や画面端に近いグリッドセルに配置された歌詞であっても、PCモニターの画面枠（ネオン枠線・ヘッダー・フッター）から外側へ絶対に飛び出さないレイアウトの安定性を100%確保。
* **未復号の暗号歌詞（スクランブルテキスト）の表示時間を延長**:
  * フレーズ境界を越えた際に即時消去されていた仕様を変更し、フレーズ終了後も **2.0秒間** 画面に残るよう猶予を追加。
  * これにより、ユーザーが歌詞を見つけてクリック・復号（ハック）できる時間的猶予が大幅に向上。
* **デコード成功時の歌詞表示時間を大幅延長**:
  * 復号（デコード）された歌詞の表示持続時間を 1.4秒 ➔ **6.4秒** (+5秒) に延長。
  * 表示時間を伸ばした分、画面上に歌詞が同時に多く残るため、以下の衝突回避・縮小施策を合わせて適用。
* **フォントサイズの大幅縮小とマージン最適化**:
  * **通常パート**: 20px ➔ **14px** に縮小。
  * **サビパート（Climax）**: 32px ➔ **20px** に縮小。
* **グリッド分割とセル排他による完璧な歌詞重なり回避＆均等分散配置**:
  - 画面のアスペクト比に応じて動的にグリッドサイズ（PCランドスケープは 4行×5列、スマホポートレートは 5行×3列 の計15〜20セル）を構築。
  - 画面上のアクティブな歌詞（`phraseTargets`）がどのセルに配置されているかを管理し、新しく出現する歌詞は完全に「空いているセル」を優先してランダム決定。
  - すべてのセルが埋まっている場合は、まだ復号（クリック）されていないアクティブなセルを保護し、復号済み（既読・消去待ち）のセルを優先上書き。
  - セル内部でランダムな位置微調整（ジッター）を加えることで、格子状 of 不自然な整列感を排除しつつ、数学的・視覚的な重なり防止を完璧に担保。
* **画面サイズに応じたモバイル・レスポンシブの強化**:
  - CSS変数 `--to-font-size` の標準フォントサイズを 14px に調整。
  - モバイル幅（`max-width: 768px`）では元の 75%（通常10.5px / サビ15px）に縮小し、パディングも `4px 8px` にコンパクト化。
  - JS側の衝突検知矩形計算も、このモバイル縮小率（75%）およびパディングと完全に同期。

## 📅 2026-05-26: [Vocal Pulse & Decryption Alignment] 物理的0ms同期およびパルス演出の整備

### 変更内容
* **TextAlive公式タイマーへの完全物理同期**:
  * 基底クラスおよび `song-takeover.js` の `update()` ループ内での手動先行アジャスト時間（+80ms）を完全廃止し、0ms物理同期へと統一。

## 📅 2026-05-25: [Secure Scramble & Web Crypto API] Web Crypto APIを用いた本格的ハッキング・スクランブル演出の実装

### 変更内容
* **AES-256-GCM暗号化を活用したスクランブル演出の実装**:
  * `window.crypto.subtle` (Web Crypto API) を用いて、シーン初期化時に非抽出（non-extractable）の AES-GCM 256bit 鍵をその場で安全に生成。
  * 歌詞テキストを動的に暗号化し、その暗号文バイト列を Base64 文字列に変換。Base64 文字列からスライディングウィンドウを介してハッカー調のスクランブル表示（`[ CLICK TO DECRYPT ]`）をリアルタイムにアニメーション描画する独創的な演出を導入。
  * ユーザーがスクランブル表示された要素をクリックすると、対応する IV と暗号文を Web Crypto API で非同期復号。
  * 復号に成功すると、文字が鮮やかにグロウ発光する本来の赤いテキストへとデコードされ、一時的に表示された後に滑らかにフェードアウトする極上のインタラクティブUXを構築。
* **ダイナミックインポート遅延の解消によるパフォーマンス大幅改善**:
  * `src/songs/BaseSong.js` の `update()` 内で毎フレーム（60fps）行われていた `import('../core/player.js')` の動的Promise解決処理を廃止し、ファイルの先頭で `playerManager` を同期インポートするよう刷新。これによってGC負荷を劇的に下げ、カクつき（Jank）を完全にゼロにしました。
* **ローカル開発時における歌詞ロード問題の修正（E2Eテストの安定稼働）**:
  * `src/core/player.js` において、ローカル開発環境（`localhost` / `127.0.0.1`）から TextAlive サーバー側へ `altLyricsUrl` を引き渡そうとしてロードエラーになる問題を防止するため、安全な Hostname 除外ガードを復旧。
